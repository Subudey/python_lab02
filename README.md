# Потоковый анализатор файлов на Python (`streamstats`)

---

## Описание проекта

В рамках лабораторной работы был разработан Python-пакет **streamstats** с интерфейсом командной строки (**CLI**). Программа читает файлы с событиями (логами) в форматах **CSV** и **JSONL**, считает по ним статистику и сохраняет итоговый отчёт в формате **JSON**.

Каждое событие состоит из четырёх полей:

* `timestamp` — время события (в формате ISO 8601, например `2026-10-20T12:00:00Z`);
* `level` — уровень события (например, `INFO` или `ERROR`);
* `source` — источник события (например, `auth` или `db`);
* `message` — текст сообщения.

Файлы читаются **потоком**: событие за событием, без загрузки всего файла в память. Интерфейс командной строки реализован с помощью библиотеки **Typer**.

# Требования и зависимости

Для работы проекта необходим **Python версии 3.11 или выше**.

Проект использует следующие библиотеки и инструменты:

| **Зависимость** | **Назначение**                                          |
| --------------- | ------------------------------------------------------- |
| Python 3.11+    | Язык программирования, на котором написан проект.       |
| Typer           | Создание интерфейса командной строки (CLI).             |
| Pydantic        | Проверка и разбор данных событий.                       |
| pytest          | Автоматическое тестирование программы.                  |
| mypy            | Статическая проверка типов.                             |
| ruff            | Проверка и форматирование кода.                         |

## Установка зависимостей

Все команды выполняются в корне проекта (там, где лежит `pyproject.toml`).

1. Создайте виртуальное окружение:

```bat
python -m venv .venv
```

2. Активируйте окружение.

В командной строке:

```bat
.venv\Scripts\activate.bat
```

3. Установите проект вместе с инструментами разработки:

```bat
pip install -e ".[dev]"
```

Команда читает зависимости из файла `pyproject.toml`: устанавливает пакет `streamstats` с библиотеками Typer и Pydantic, а также инструменты разработки (pytest, mypy, ruff).

# Возможности программы

## Форматы входных данных

### JSONL

Каждая строка файла — отдельный JSON-объект с полями события:

```text
{"timestamp": "2026-10-20T10:00:00Z", "level": "INFO", "source": "auth", "message": "вход"}
{"timestamp": "2026-10-20T11:00:00Z", "level": "ERROR", "source": "db", "message": "таймаут"}
```

### CSV

Первая строка — заголовок с названиями полей, дальше по одному событию в строке:

```text
timestamp,level,source,message
2026-10-20T10:00:00Z,INFO,auth,вход
2026-10-20T11:00:00Z,ERROR,db,таймаут
```

Файлы могут содержать кириллицу, кодировка входных и выходных файлов — **UTF-8**.

## Что считает анализатор

1. Общее число событий (`total`).
2. Число событий по уровням (`by_level`).
3. Число событий по источникам (`by_source`).
4. Пять источников с наибольшим числом ошибок (`top_error_sources`).
5. Время первого и последнего события (`first_timestamp`, `last_timestamp`).
6. Число пропущенных некорректных строк (`skipped`).

Можно передать сразу несколько файлов: статистика по ним объединяется в один отчёт.

## Параметры команды `analyze`

| **Параметр**     | **Назначение**                                                              |
| ---------------- | --------------------------------------------------------------------------- |
| `INPUTS...`      | Один или несколько входных файлов (обязательный аргумент).                  |
| `--format`       | Формат входных файлов: `csv` или `jsonl` (обязательный параметр).           |
| `--output`       | Путь к JSON-файлу отчёта (обязательный параметр).                           |
| `--skip-invalid` | Пропускать некорректные строки вместо остановки с ошибкой (необязательный). |

# Описание алгоритма решения задачи

1. Пользователь запускает команду `python -m streamstats analyze` и передаёт входные файлы, формат и путь к отчёту.
2. Для каждого файла выбирается парсер: `csv_parser()` или `jsonl_parser()`.
3. Парсер читает файл построчно и превращает каждую строку в событие. Проверяются все поля события, включая допустимость уровня и формат времени.
4. Если строка некорректна, возможны два варианта:
   * без `--skip-invalid` разбор останавливается с ошибкой `InvalidEventError`, в сообщении указываются файл и номер строки;
   * с `--skip-invalid` строка пропускается, выводится предупреждение, а счётчик `skipped` увеличивается на 1.
5. Функция `analyse_files()` по мере поступления событий обновляет статистику: общий счётчик, счётчики по уровням и источникам, счётчик ошибок по источникам, первую и последнюю метки времени.
6. Функция `build_report()` превращает собранную статистику в словарь, готовый для сохранения в JSON.
7. Функция `write_report()` создаёт недостающие каталоги и записывает отчёт в выходной файл.

# Обработка ошибок

Программа проверяет корректность данных и выводит сообщения об ошибках.

| **Ошибка**                                  | **Что происходит**                                                       |
| ------------------------------------------- | ------------------------------------------------------------------------ |
| Некорректная строка (неверный уровень и т. д.) | Остановка с кодом **2**, в сообщении номер строки. Отчёт не создаётся.   |
| Некорректная строка при `--skip-invalid`    | Строка пропускается, выводится предупреждение, `skipped` увеличивается.  |
| Не указан `--output` или `--format`         | Typer выводит сообщение вида `Missing option '--output'`, код выхода **2**. |
| Пустой файл                                 | Событий нет, ошибки нет, в отчёте `total: 0`.                            |

Сообщения об ошибках выводятся в `stderr`, а при остановке из-за некорректных данных программа завершается с кодом **2**.

# Описание файлов проекта

### `parsers.py`

Содержит функции `csv_parser()` и `jsonl_parser()`, которые читают файл построчно и возвращают события, а также класс `ParseStats` со счётчиком пропущенных строк.

### `analysis.py`

Содержит класс `Stats` со всей собранной статистикой и функцию `analyse_files()`, которая обрабатывает один или несколько файлов и объединяет результат.

### `report.py`

Содержит функцию `build_report()`, которая готовит статистику к сохранению, и функцию `write_report()`, которая записывает отчёт в JSON-файл.

### `errors.py`

Содержит исключение `InvalidEventError` для некорректных событий.

### `__main__.py`

Создаёт интерфейс командной строки с помощью Typer и обрабатывает запуск команды `analyze`.

### `tests/`

Содержит автоматические тесты для проверки парсеров, кодировки и интерфейса командной строки.

# Примеры работы программы

## Подготовка файлов для примеров

Для примеров создайте в корне проекта три файла (кодировка UTF-8).

`good.jsonl` — корректный файл JSONL:

```text
{"timestamp": "2026-10-20T10:00:00Z", "level": "INFO", "source": "auth", "message": "вход"}
{"timestamp": "2026-10-20T11:00:00Z", "level": "ERROR", "source": "db", "message": "таймаут"}
{"timestamp": "2026-10-20T12:30:00Z", "level": "ERROR", "source": "db", "message": "обрыв"}
{"timestamp": "2026-10-20T13:00:00Z", "level": "INFO", "source": "auth", "message": "выход"}
```

`bad.jsonl` — файл JSONL с ошибкой (в третьей строке недопустимый уровень `BANANA`):

```text
{"timestamp": "2026-10-20T10:00:00Z", "level": "INFO", "source": "auth", "message": "ok"}
{"timestamp": "2026-10-20T11:00:00Z", "level": "ERROR", "source": "db", "message": "x"}
{"timestamp": "2026-10-20T12:00:00Z", "level": "BANANA", "source": "auth", "message": "x"}
```

`good.csv` — корректный файл CSV с теми же событиями, что и `good.jsonl`:

```text
timestamp,level,source,message
2026-10-20T10:00:00Z,INFO,auth,вход
2026-10-20T11:00:00Z,ERROR,db,таймаут
2026-10-20T12:30:00Z,ERROR,db,обрыв
2026-10-20T13:00:00Z,INFO,auth,выход
```

## Корректный файл JSONL

```bash
python -m streamstats analyze good.jsonl --format jsonl --output out/report.json
```

Программа завершается с кодом **0** и создаёт файл `out/report.json`.

**Содержимое отчёта**

```json
{
  "total": 4,
  "by_level": {
    "INFO": 2,
    "ERROR": 2
  },
  "by_source": {
    "auth": 2,
    "db": 2
  },
  "top_error_sources": [
    {
      "source": "db",
      "count": 2
    }
  ],
  "first_timestamp": "2026-10-20T10:00:00+00:00",
  "last_timestamp": "2026-10-20T13:00:00+00:00",
  "skipped": 0
}
```

## Корректный файл CSV

```bash
python -m streamstats analyze good.csv --format csv --output out/report_csv.json
```

Отчёт получается таким же, как для JSONL-файла с теми же событиями.

## Файл с ошибкой

```bash
python -m streamstats analyze bad.jsonl --format jsonl --output out/bad.json
```

Программа останавливается с сообщением об ошибке и номером строки (`строка 3`), код выхода **2**, файл `out/bad.json` не создаётся.

## Пропуск некорректных строк

```bash
python -m streamstats analyze bad.jsonl --format jsonl --output out/skip.json --skip-invalid
```

В консоль выводится предупреждение о пропущенной строке:

```text
WARNING: Пропущена строка: bad.jsonl, строка 3: ...
```

В отчёте будет `total: 2` и `skipped: 1`.

## Несколько файлов

```bash
python -m streamstats analyze good.jsonl good.jsonl --format jsonl --output out/two.json
```

Статистика объединяется, в отчёте `total: 8`.

# Запуск программы

Общий вид команды:

```bash
python -m streamstats analyze PATH [PATH ...] --format {csv,jsonl} --output REPORT.json [--skip-invalid]
```

Пример:

```bash
python -m streamstats analyze User1/app.jsonl --format jsonl --output reports/report.json
```
